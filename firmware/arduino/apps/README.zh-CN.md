# Mini Synth Keyboard 正式应用

[English](README.md)

## `mini_synth_v1`

这是一份已通过实板使用验证的可演奏正式固件，包含多应用外壳、30 首文件曲库、持久化设置、全局 BLE 游戏键盘和 MUSB v1 存储管理。音高校正开关已在更换全频喇叭后的设备上完成烧录和听感验证。

### Play 与音频

- 七个低电平有效音符键演奏 C-D-E-F-G-A-B，并支持和弦。独立的 1 kHz 输入任务提供 5 ms 非阻塞消抖；独立的 4 ms 音频任务持续向 I2S 送数。
- Play 的八度模式在 Settings 中选择：
  - `HOLD`（默认）：按住 SW8 选择 C3；不按功能键为 C4；按住 SW9 选择 C5。同时按住两键仍是全局 Home/BLE 手势，不用于选择八度。
  - `LATCH`：单独按下并释放 SW8 后下降一个八度，单独按下并释放 SW9 后上升一个八度，范围限制在 C3–C5。锁定的八度在本次开机期间切换应用后仍保留，重启后恢复 C4。如果 SW8+SW9 被用于 Home/BLE 手势，则不会提交八度变化。
- Play 中已经发声的音符在切换八度时保留已确认的 12 ms smoothstep 平滑滑音；新触发的音符直接从目标八度起音。
- Play 音色只能在 Settings 中选择；SW8/SW9 不再通过双击切换 Play 音色。Song 仍保留独立的 SW8/SW9 音色控制。
- `PITCH EQ`（音高校正）是同时作用于 Play 和 Song 的按音高调整响度开关，**默认关闭**，不会改变音符频率。它是为原先谐振频率约 950 Hz、在约 800 Hz–1.2 kHz 区域有明显峰值的小喇叭准备的：这类喇叭会让高音相对过强，开启后用 21 音衰减表逐步降低中高音输出，并对 Song 半音插值。该区间是原喇叭的适配范围，不是对所有扬声器的通用分界。
- 开启时，`8BIT`、`ORGAN` 和 `PIANO` 保留 MIDI 60–71 的 +3 dB、MIDI 72 及以上的 +6 dB 额外增益，低于 MIDI 60 不变；和弦归一化使用原校准包络以保留相对提升。关闭时，音高表、额外八度增益和归一化中的音高校正权重全部旁路为 1.0；和弦归一化本身仍工作。
- 无论开关状态，均保留音色整体增益、波形与包络、全局音量、防削波限幅和 `MASTER_PEAK=18000`。音频每块读取一次设置快照，新起音锁存校正状态，已有释音尾音保持原增益；Play 八度切换仍按该音符锁存状态进行原有的 12 ms smoothstep 过渡。
- 全局音量在混音/归一化之后、最终限幅和 `MASTER_PEAK` 之前作用于 Play 与 Song。范围为 0%–100%，每级 10%；100% 保持已验收的原始输出路径。
- 启动后检测到连续 100 ms 有效数字静音，才启用 NS4168，并保持启用，避免每次按键都产生功放使能瞬态。冷启动不会等待 USB Serial。

### Home、Settings 与应用外壳

- 固件仍直接启动到 Play。按住 SW8+SW9 1 秒进入 Home。C/D/E/F/G/A/B 分别选择 Play/Song/Loop/Beat/Pet/Keyboard/Game；SW8 打开 Settings；SW9 恢复上一个可恢复应用。每次应用切换后，在九个键全部释放前都会屏蔽输入。
- Settings 使用独立 `Preferences` NVS 命名空间，与 BLE 配对信息无关。记录不存在、损坏或不兼容时，回退为音量 100%、八度模式 HOLD、Play 音色 SINE、音高校正 OFF。13 字节 v2 记录严格验证开关为 0/1，并将其纳入校验和；读取有效的 12 字节 v1 记录时保留原音量、八度模式和 Play 音色，只补入音高校正 OFF，后续保存设置时写为 v2。加载不会清空 NVS、BLE 配对或 FFat。
- Settings 操作：C/D 循环选择上一项/下一项，E/F 减小/增大当前值，G 恢复当前项默认值。四项 `VOLUME`、`OCT MODE`、`PLAY SOUND`、`PITCH EQ: OFF/ON` 在三行可见区域内滚动，底部提示与 BLE 标志保留。选中音高校正时，E 关闭、F 开启、G 恢复关闭。与其他页面一致，按住 SW8+SW9 返回 Home。
- Loop、Beat、Pet 和 Game 仍为安全的 `COMING SOON` 占位应用，并输出数字静音。

### Song 曲库与控制

- Song 从 FFat 根目录显示最多 30 个有效 MSPKG v1 `SEQUENCE` 文件（`.mspkg` 或 `.msp`）。顺序由不区分大小写的文件名排序确定；音乐库管理器使用 `01-` 到 `30-` 前缀保留用户顺序。
- 文件歌曲目录条目只长期保留显示元数据、来源标识、时长/事件数量和路径。稳定状态下，只有当前选中的文件歌曲持有已分配的 `SongEvent[]`；扫描其他文件时会完整验证，并立即释放其临时事件数组。四首内嵌恢复曲保持为不可变 Flash 数组。
- E/F 会停止播放、改变选择，并通过 `loopTask` 异步请求加载。音频任务绝不访问 FFat，也不会阻塞。选择加载沿用音频目录门控：音频端先确认到达安全边界，之后才释放旧的选中数组并安装新数组。OLED 显示 `LOAD` 或 `FAILED`；加载成功前，C 和 D 不能开始播放。
- 启动时若存在有效文件歌曲，会选择并加载索引 0。若 FFat 不存在、损坏、未挂载、为空或没有有效包，则显示四首内嵌歌曲作为后备。
- Song 页面保留状态、标题、音色、时间进度和操作提示，并新增 `01/30` 形式的两位序号/总数显示。
- Song 操作：C 切换播放/暂停，D 从头播放，E/F 选择上一首/下一首但不自动播放，SW8/SW9 循环切换 Song 音色，按住 SW8+SW9 返回 Home。
- 加载器使用 `FFat.begin(false)` 挂载，绝不自动格式化。它会检查容器尺寸、metadata/payload CRC-32、来源哈希重复、事件数量、音高/时间顺序和实际峰值复音数。

### BLE 与 USB 不变量

- BLE 是全局服务，不归 Keyboard 页面单独所有。按住 SW8+SW9 1 秒返回 Home；继续按到 3 秒，会打开原有的 30 秒切换设备窗口。固件保留配对关系，只临时拒绝用户明确离开的对端，并在所有页面维持 `B-` / `B30..B01` / `B+` 状态标记。
- Keyboard 继续使用相同的两字节 NKRO BLE HID 游戏键盘映射：上排 SW1/SW2/SW3/SW8 = Q/W/E/R，下排 SW4/SW5/SW6/SW7 = A/S/D/F，SW9 = 左 Alt。Alt 会抑制 R；退出时释放全部按键；重连后需经过全释放门控；BLE API 调用只在低优先级 BLE 任务中执行。
- MUSB v1 命令和 payload 保持不变。上传仍先写隐藏的 FFat 临时文件，提交前验证，并使用“备份 + 重命名”回滚。上传/删除后的刷新会重新扫描最多 30 首歌曲，并通过同一个原子音频门控留下一个已正确加载的选中歌曲。`INIT_STORAGE` 是唯一需要明确确认的格式化路径，而且只影响 FFat 音乐分区。

### 音高校正与喇叭匹配

主机测试在硬件桩环境中执行正式源码的设置函数和完整音频任务，覆盖 v1 迁移、v2 往返与校验、21 个 Play 音和 128 个 MIDI 音高的四音色增益、菜单滚动、增益锁存、八度平滑及输出限幅。提供修改前源码备份时，还会逐采样比较开启校正后的输出与旧音频任务是否一致。运行方法见[主机测试说明](../tests/host_pitch_eq/README.md)。

原小喇叭或其他在约 800 Hz–1.2 kHz 有明显谐振峰、导致高音偏响的扬声器，可开启校正；响应较平直、能够覆盖本机音域的全频喇叭通常保持关闭。新版较大全频喇叭配合 OFF 已由用户完成烧录和实板听感验证。更换未知喇叭时仍应从较低总音量比较 ON/OFF，不能只按商品名称判断。MUSB 协议、音乐管理器、歌曲格式、分区和板卡配置均不变。

所需库：

- `MiniSynthBoard`（项目内库或已安装 ZIP）；
- Oliver Kraus 的 `U8g2`；
- Arduino-ESP32 3.3.11 内置的 `ESP_I2S`、`BLE`、`FFat` 和 `Preferences`。

正式应用有意不等待 USB Serial，也不输出大量同步启动/按键日志；这些行为曾在 USB 反压时造成冷启动变慢和 OLED 延迟。请使用 `config/board.ps1` 中的精确 FQBN 编译，并在实板验证冷启动时间、OLED 响应、设置持久化、八度行为、30 首歌曲浏览/加载、音频平衡、BLE 切换和 MUSB 刷新。若出现复位、USB 断连、明显失真、异味、快速发热或 TP2 电压不稳，应立即停止。
