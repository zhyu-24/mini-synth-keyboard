# Mini Synth 音乐库管理器

面向 Windows 用户的文件歌曲管理工具。它通过设备已有的 USB 串口协议读取、转换、删除并同步 MSPKG；**串口始终由用户在运行时选择，不会写死 COM 号**。

## 快速开始（Windows 图形界面）

1. 安装 Python 3.10 或更高版本。
2. 安装 USB 依赖：

   ```bat
   py -3 -m pip install pyserial
   ```

3. 如需直接添加 MusicXML，再安装现有转换器所需的 NumPy：

   ```bat
   py -3 -m pip install numpy
   ```

4. 用 USB 数据线连接 Mini Synth，双击 `启动音乐库管理器.bat`。
5. 选择设备的 COM 口，点“连接 / 刷新状态”。
6. 在右侧批量添加最多 30 首歌曲：点“导入并保留设备歌曲”只新增/覆盖同名歌曲；点“按右侧顺序重排设备歌曲…”会用完整本地源整理现有曲库编号；点“精确同步到设备”会让设备音乐库与右侧列表**完全一致**。

图形界面不会在注册表或其他隐蔽位置记住歌曲/串口。需要保留选择时，可显式保存一个 JSON 项目文件；再次打开项目时会重新验证或转换源文件。

设备列表和目标列表都带垂直滚动条，可在普通 Windows 显示器上浏览 30 个条目；批量添加、批量移除、上移/下移排序、清空列表、项目保存/打开功能保持不变。同步计划在歌曲较多时会折叠长文件名列表，避免窗口被 30 个名字撑开。

## 支持的源文件

- `.mspkg`：验证 MSPKG v1 SEQUENCE 容器、尺寸、CRC、TLV 和序列基本结构后使用；
- `.msp`：与 `.mspkg` 相同，仅使用短扩展名；
- `.musicxml` / `.xml`：调用仓库现有 `tools/media-import/convert_musicxml.py` 转换，并保留转换器输出的预览 WAV、manifest 和兼容性报告在工作目录中。

设备最多保存 30 首文件歌曲。管理器为每首歌生成安全、确定性的 ASCII 文件名，并以两位数 `01-` 至 `30-` 前缀保持设备目录顺序。中文/Unicode 文件名会生成稳定哈希，不会因为无法转成 ASCII 而冲突。

> MusicXML 转换器要求单个 `score-partwise` part。它会展开非嵌套的顺序 `forward/backward` 反复、合法 `times` 次数及常见第一/第二结尾；嵌套/重叠反复、未闭合结构或 D.C./D.S./Segno/Coda/Fine 跳转会明确拒绝，不会静默按错误顺序生成歌曲。

## 增量导入、同名覆盖与个别删除

“导入并保留设备歌曲”不会删除未选中的设备歌曲：

1. 读取设备当前文件并执行容量预检；
2. 新歌始终使用 `01..30` 中最小的空闲编号；例如设备剩余 `02、03` 时，两首新歌使用 `01、04`；
3. 同名歌曲按“忽略两位编号前缀、`.mspkg/.msp` 扩展名和大小写”匹配；覆盖时复用原设备文件名和顺序位置；
4. 只原子上传新增或覆盖项目，保留其他设备文件；
5. 再次读取设备并严格核验最终文件名和大小。

设备列表支持多选，使用“删除设备选中歌曲…”可删除一首或多首文件歌曲。删除前会显示完整确认列表，连续删除会等待设备曲库刷新完成。固件内置备用歌曲不受影响。

如果设备或待导入列表含多个相同逻辑名称，管理器会在写入前停止并报告歧义，不会猜测覆盖目标。

## 按本地源重排设备歌曲

设备现有 MUSB 协议不能下载或重命名文件，因此重排必须使用设备全部歌曲对应的本地 MusicXML/MSP/MSPKG：

1. 在右侧加入与设备逻辑歌曲一一对应的全部本地源，用“上移/下移”排好顺序；
2. 点击“按右侧顺序重排设备歌曲…”；管理器会拒绝缺少、多出、同名歧义或大小不一致的源文件；
3. 确认框会列出当前顺序、新顺序、改名数量和容量预检；
4. 管理器使用本地内容重写连续的 `01..N` 文件名，并在结束后严格核对名称、大小、数量和顺序。

这个功能不增加或删除逻辑歌曲，但会删除旧编号文件并重新上传本地内容。它不同于“精确同步”：重排要求两边逻辑歌曲集合完全相同，精确同步则允许本地目标增加或删除曲目。

## 普通同步不等于刷固件

“同步到设备”只修改设备 FFat 音乐分区里的 `.mspkg/.msp` 文件：

1. 读取设备现有文件；
2. 删除目标列表中没有的文件；
3. 逐个原子上传/覆盖所有目标歌曲（设备以临时文件和回滚方式提交）；
4. 再次读取设备，严格核对最终文件名和大小集合。

在任何删除或上传发生前，管理器还会做保守的目标容量预检：主机常量按固件 FFat 分区容量 `0x9E0000` 字节计算，并至少预留分区的 5% 加 128 KiB，供 FAT 元数据、磨损均衡以及原子上传的临时/备份文件使用。替换文件时，预检会按“当前文件 + 回滚备份 + 新临时文件”可能同时存在来估算峰值；因此它可能比设备实际使用更保守。若目标文件总量或同步峰值超过安全上限，GUI/CLI 会用中文说明分区容量、预留量、目标总量、估算峰值和超出量，并在修改设备前拒绝同步。协议不会为此新增查询剩余空间的命令。

单个包仍受现有 `MAX_FILE_BYTES` 限制。30 首是条目数量上限，不表示 30 个最大尺寸包一定能装入 FFat。

它**不会编译或烧录 ESP32 固件**，不会修改 BLE 配置，也不会删除固件内置的备用歌曲。只要设备中至少存在一首有效文件歌曲，Song 页面就只显示用户同步的文件曲库；文件曲库为空、损坏或无法挂载时才显示四首内置备用歌曲。固件刷写仍应使用项目单独的 Arduino/烧录流程。

## 初始化 / 修复音乐存储

此操作只用于 FFat 音乐存储无法挂载或损坏的恢复场景。它会格式化音乐分区，永久删除全部文件歌曲；不会刷写固件，也不会修改内置备用歌曲。

GUI 要求输入完整确认文字：

```text
ERASE-MUSIC-LIBRARY
```

普通同步不自动格式化存储。命令行也必须提供同样的确认文字。

## 命令行 / 本地 Agent 示例

在本目录运行，或给脚本使用完整路径。以下 `COM7` 只是示例，必须替换为现场发现的串口。

```bat
rem 查找候选串口
py -3 music_library.py ports

rem 查看设备状态和文件歌曲
py -3 music_library.py show --port COM7

rem 仅转换/验证，结果复制到工作目录并输出 RESULT_JSON
py -3 music_library.py prepare "D:\Music\歌曲.musicxml" "D:\Music\ready.mspkg" --output "D:\MiniSynthWork"

rem 一条命令转换并使设备音乐库与选择完全一致（最多 30 首）
py -3 music_library.py sync --port COM7 "D:\Music\歌曲.musicxml" "D:\Music\ready.mspkg" --work-dir "D:\MiniSynthWork"

rem 保留设备现有歌曲，只新增或覆盖同名歌曲
py -3 music_library.py import --port COM7 "D:\Music\新歌.musicxml" "D:\Music\ready.mspkg" --work-dir "D:\MiniSynthWork"

rem 使用设备全部歌曲对应的有序本地源，把设备文件连续重排为01..N
py -3 music_library.py reorder --port COM7 "D:\Music\第一首.msp" "D:\Music\第二首.msp" --work-dir "D:\MiniSynthWork"

rem 删除一个或多个设备文件（文件名可先用 show 查询）
py -3 music_library.py delete --port COM7 01-song.mspkg 02-demo.mspkg

rem 明确清空全部文件歌曲（空 source 只有带 --allow-empty 才合法）
py -3 music_library.py sync --port COM7 --allow-empty

rem 破坏性初始化/修复
py -3 music_library.py init-storage --port COM7 --confirm ERASE-MUSIC-LIBRARY
```

每次 CLI 操作都会输出简洁进度，最后一行以 `RESULT_JSON=` 开头，便于本地 Agent 可靠解析。失败时也会输出 `ok: false` 的结果行并返回非零退出码。

## 故障处理

- 找不到 COM 口：重新插拔 USB，确认使用数据线，点击“刷新串口”；
- COM 口被占用：关闭 Arduino 串口监视器或其他终端程序；
- 超时：确认选择的是 Mini Synth 的 USB 串口，再重新连接；
- MusicXML 提示缺少 NumPy：执行 `py -3 -m pip install numpy`；
- 音乐存储显示不可用：先重启/重新连接；只有确定存储损坏且接受清空全部文件歌曲时，才使用“初始化 / 修复音乐存储”。
